01 Introduction to Operating Systems

Before Linux, understand the job every operating system does.

A computer is just electronics — a processor (CPU) that does maths, memory (RAM) that holds work-in-progress, and storage (disk) that keeps files. On its own, that hardware doesn't know how to open a photo or run a browser.

🍽️
AnalogyAn operating system is the manager of a busy restaurant. Customers (apps) place orders, but they never walk into the kitchen. The manager (the OS) decides which chef (CPU) cooks what, how counter space (memory) is shared, where dishes are stored (files), and makes sure two orders don't collide. That coordination is the operating system.

Hardware vs Software

🔩 Hardware

The physical parts you can touch — CPU, RAM, disk, keyboard, network card.

💾 Software

Instructions that tell hardware what to do — the OS itself, plus apps like a browser or editor.

What an operating system is responsible for

⚙️ Process management

Starts, pauses and stops running programs, and shares the CPU between them.

🧠 Memory management

Gives each program the RAM it needs and protects programs from each other.

📁 File-system management

Organises data into files and folders on disk and controls access to them.

🖨️ Device management

Talks to hardware (disks, GPUs, printers) through drivers.

🌐 Network management

Sends and receives data over the network so machines can talk.

🔐 Security & users

Decides who may do what — logins, permissions, isolation.

02 History of Linux

Where it came from — and why that story still shapes how Linux works.

Linux didn't appear out of nowhere. It's the latest chapter in a 50-year story that began with UNIX at Bell Labs.

1969UNIX is born at Bell Labs — a small, elegant OS built by programmers, for programmers.
1970s–80sUNIX spreads & splits — BSD UNIX from Berkeley, plus commercial versions: IBM AIX, Sun Solaris, HP-UX.
1983The GNU Project — Richard Stallman starts building free UNIX-compatible tools (the “GNU” utilities you still use today).
1991The Linux kernel — a Finnish student, Linus Torvalds, writes a free UNIX-like kernel and shares it with the world.
TodayDistributions package the Linux kernel + GNU tools into ready-to-use systems: Ubuntu, Debian, Fedora, Rocky Linux, CentOS, Arch.
💡
The UNIX philosophy“Write programs that do one thing well, and work together.” This is why Linux gives you dozens of tiny commands you can combine (with a | pipe) instead of one giant program. You'll feel this everywhere.

Why Linux succeeded

  • Free & open source — no licence fees; the code is public.
  • A global community — thousands of contributors fix and improve it daily.
  • It runs anywhere — from a $5 sensor to the world's fastest supercomputers.

👤 User space

Where your apps and the shell live. If a program here crashes, the system keeps running.

🛡️ Kernel space

Privileged core code that talks directly to hardware. Protected from ordinary programs.

📞 System calls

The “front desk” — how a program in user space politely asks the kernel to do something (open a file, use the network).

🔌 Device drivers

Kernel modules that know how to speak to a specific piece of hardware.

🚗
AnalogyThe kernel is the engine, the shell is the steering wheel & pedals, and applications are you deciding where to go. You never touch the engine directly — you send instructions through the controls (system calls).

05 The Linux File System

One tree to rule them all — starting at /.

📄
Golden ruleIn Linux, everything is a file — your documents, yes, but also devices (your disk is /dev/sda), running processes, even system settings. Learn to navigate files and you can control the whole system.

Unlike Windows (with C:, D: drives), Linux has a single tree that starts at the root directory /. Everything hangs off it.

/ ├── home # personal folders — /home/student ├── root # the admin user's home ├── etc # system-wide configuration files ├── var # things that change: logs, mail, caches ├── usr # installed programs & their files ├── bin # essential commands (ls, cp, cat) ├── sbin # system/admin commands ├── opt # optional / third-party software ├── tmp # temporary files (wiped on reboot) ├── dev # devices (disks, USB) as files ├── proc # live view of the kernel & processes └── boot # files needed to start Linux
🧭
Remember these three/home is where your stuff lives, /etc is where settings live, and /var/log is where you look when something breaks.

07 Users and Login

Linux was multi-user from day one.

Many people (or programs) can use one Linux machine at once, each kept separate. There are two kinds of accounts you must know:

🧑 Normal user

Everyday account (e.g. student). Can only touch its own files. Safe.

👑 root (superuser)

The all-powerful admin. Can change anything — including break everything. Use with care.

⚠️
Golden safety ruleDo your normal work as a normal user. Only borrow admin powers when you truly need them, using sudo in front of a single command. Never “live” as root.

Ways to log in

  • Console login — typing your username & password at the machine itself.
  • SSH — logging into a remote machine securely over the network (how you reach cloud servers):
ssh student@server-ip        # connect to a remote Linux machine

08 The Shell & Terminal

The single most important skill in this whole guide.

🖥️ Terminal

The window you type into — a text screen for talking to the computer.

🐚 Shell

The program inside that window that reads your commands and runs them. The most common one is Bash. (Zsh is a popular modern alternative.)

🗣️
AnalogyThe terminal is the phone; the shell is the translator on the line who turns your words into instructions the system carries out.

Reading a command

ls -l /home/student
# └┬┘  └┬┘  └──────┬──────┘
#  command option    argument

A command has three parts: the command (what to do), options (how to do it, usually starting with -), and arguments (what to do it to).

10 File Permissions

The heart of Linux security — who can do what.

Every file and folder answers three questions for three groups of people. The questions are Read (r), Write (w), and Execute (x). The people are the Owner, the Group, and Others.

 │ │  │  └ others: r--  (read only)
 │ │  └─── group:  r-x  (read + execute)
 │ └────── owner:  rwx  (read + write + execute)
 └──────── type:   -    (- = file, d = directory)

11 Process Management

Everything running is a process — here's how to watch and control them.

A process is a running program. Each has a unique number (PID). Processes can start other processes (a parent starting a child). Some run in the foreground (you wait for them); others in the background (they run while you keep working).

CommandWhat it does
ps auxList all running processes
top / htopLive, updating view of CPU & memory use
kill 1234Politely stop the process with PID 1234
kill -9 1234Force-stop (last resort)
killall firefoxStop every process by name
jobs · bg · fgManage background/foreground jobs
📊
Your go-to toolRun htop (or top) to see, at a glance, what's using your CPU and memory — the first thing an engineer checks when a machine is slow.

12 Installing Software

No hunting for “.exe” files — Linux uses package managers.

A package manager installs, updates and removes software for you from trusted online repositories — handling dependencies automatically. Which one you use depends on the distribution family:

🟠 Debian / Ubuntu

sudo apt update            # refresh the catalog
sudo apt install git       # install a package
sudo apt upgrade           # update everything

🔴 RedHat / Fedora / Rocky

sudo dnf install git       # (older: yum)
sudo dnf update

14 Services (systemd)

The background programs that keep a server running.

A service (or daemon) is a program that runs quietly in the background — a web server, a database, your monitoring script. On modern Linux, the manager in charge of starting and supervising them is systemd. It's also the first thing that runs when Linux boots.

CommandWhat it does
systemctl status nginxIs the service running? show details
sudo systemctl start / stop nginxStart or stop it now
sudo systemctl enable nginxStart it automatically at boot
journalctl -u nginxRead that service's logs
🔧
When something won't startsystemctl status tells you if it failed; journalctl -u <service> tells you why. This pair solves most server problems.

Surviving vi — the one thing beginners must know

vi has modes. This trips everyone up once:

To…Do this
Type textPress i (insert mode)
Stop typingPress Esc (back to command mode)
Save & quitType :wq then Enter
Quit without savingType :q! then Enter
😅
The classic trap“How do I exit vim?” is a famous beginner panic. The answer: press Esc first, then type :q! to leave without saving. You're welcome.

16 Shell Scripting

Turn commands you repeat into a reusable program.

A shell script is just a text file full of commands. It's how you automate — backups, deployments, health checks. Scripts understand variables, conditions, loops and functions.

#!/bin/bash
# greet.sh — a first script

name="$1"                 # $1 = first argument

if [ -z "$name" ]; then
    name="world"
fi

for i in 1 2 3; do
    echo "($i) Hello, $name — welcome to Linux!"
done
chmod +x greet.sh      # make it runnable
./greet.sh Ada         # run it with an argument
🧩
The building blocksVariables store values · conditions (if) make decisions · loops (for/while) repeat work · functions group steps · arguments ($1 $2) pass input in.

Environment variables are named values available to your shell and the programs it runs. A few you'll meet constantly:

19 Linux Security

A few habits that keep systems safe.

🔑 Least privilege

Use a normal account; reach for sudo only when needed. Never browse or code as root.

🔐 SSH keys

Prefer key-based login over passwords; disable root SSH login.

🧱 Firewall

Open only the ports you need: sudo ufw allow 22, then sudo ufw enable.

🔏 Permissions

Keep private files at 600; don't chmod 777 to “fix” problems.

🔄 Updates

Patch regularly — most breaches exploit known, unpatched bugs.

📑 Logs

Watch /var/log/auth.log for suspicious logins.

🚫
Never do thischmod 777 gives everyone full control of a file — a classic security hole. And sudo rm -rf / tries to delete the entire system. Treat both as red buttons.

📖 Mini Glossary

Plain-English definitions for the words that come up most.

Kernel
The core of Linux. It manages the CPU, memory, files and devices, and sits between your programs and the hardware.
Shell
The program that reads the commands you type and runs them. Bash is the most common.
Distribution (“distro”)
A ready-to-use Linux system = the kernel + tools + package manager. Examples: Ubuntu, Debian, Fedora.
root / sudo
root is the all-powerful admin user. sudo lets a normal user run one command as root, safely.
Process
A running program, identified by a number (PID). ps and top show them.
Daemon / Service
A program that runs in the background (e.g. a web server), managed by systemd.
Package manager
A tool (apt, dnf) that installs and updates software from trusted repositories.
Repository
An online catalog of software your package manager can install from.
SSH
Secure Shell — the standard way to log into a remote Linux machine over the network.
Permissions (rwx)
Rules for who can read, write or execute a file — for the owner, group and others.
